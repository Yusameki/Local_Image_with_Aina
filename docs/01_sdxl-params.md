# SDXL 参数基线

> 这份文档只讲**参数**：模型组合、采样器、步数、分辨率、以及它们之间的关系。
> 不包含任何提示词正文——具体的 Prompt 与工作流 JSON 属于个人配方，不在本仓库范围内。
> 把它放在第一篇，是因为后面所有对比都需要一个基线。

---

## 1. 参数总表

| 项 | 取值 |
|---|---|
| 底模类型 | SDXL 系（Eps-pred 110%） |
| 附加模块 | 画师风格 LoRA `0.6` + 人物质感 LoRA `0.5`（双叠） |
| 采样器 | `euler_ancestral` |
| 调度 | 默认 |
| 步数 | `28` |
| CFG | `5.0` |
| 分辨率 | `768 × 1664` |
| 高清修复 | 关闭（一次出图） |
| 批量 | 1 张 / 次 |

---

## 2. 为什么是这几个数

### 2.1 步数 28

SDXL + Eps-pred 在 25–30 步之间基本收敛。
再往上加，细节增长很少，但每张的耗时线性上升；往下减到 20 以下，笔触明显变硬、边缘出现「没画完」的感觉。

`28` 是这套组合里性价比最高的一档，也是后面所有矩阵测试的固定值。

### 2.2 CFG 5.0

CFG 控制「多大程度听提示词」。

- 低于 4：画面更自由，但容易偏离描述；
- 5.0：既能守住描述，又保留 LoRA 带来的笔触松弛感；
- 高于 7：颜色开始发硬、对比过强，画风 LoRA 那种「淡」会被压掉。

> ⚠️ 这个数字**不能跨模型套用**。
> 后来 MOSS-Image 的推荐值是 CFG 3，两层原因：
> 一是架构不同（DiT vs UNet），二是文本编码器不同（LLM 式 vs CLIP 式）。
> **CFG 是个无量纲的相对量，换架构必须重新标定，不能照搬。**

### 2.3 分辨率 768 × 1664

三个理由：

1. 都是 16 的整数倍（768/16=48，1664/16=104），不触发对齐问题；
2. 比例 1 : 2.167 ≈ 手机竖屏；
3. 总像素 1.28M，正好在 SDXL 最稳的区间（1M 附近），再往上容易出现「局部过密、整体反而糊」。

> 后来 MOSS 用的 `832 × 1808` 是同一个思路的延续：
> 16 的倍数 + 同样的长宽比 + 落在该模型推荐的总像素档（1.5M）。

### 2.4 双 LoRA 的权重分配

两个 LoRA 叠加时，权重不是在「相加」，而是在**争夺同一批注意力通道**：

| 组合 | 表现 |
|---|---|
| 画风 0.6 + 人物 0.5 | 笔触稳、人物质感在，是我们要的平衡点 |
| 画风 1.0 单独上 | 笔触最强，但人物结构开始漂 |
| 两个都 ≥ 0.8 | 互相打架，出图偏灰、细节糊 |

经验值：**两个 LoRA 权重之和控制在 1.1 附近**，超过 1.4 大概率开始互相破坏。

## 3. 参数与 LoRA 的边界

这套参数有一个隐含前提：**画风来自 LoRA，不来自提示词**。

所以提示词里不写任何风格/媒介/笔触类词汇，只写「画什么」。
一旦同时用 LoRA 和风格词去争「笔触」这个维度，结果通常是两头都不像。

> 这条规则**只在有画风 LoRA 时成立**。
> 没有 LoRA 的模型（例如纯 base 的 MOSS）必须把风格描述加回提示词，
> 否则画面会退化成没有性格的默认风格。

---

## 4. 负向词的作用边界

负向词能做的事情比大多数人以为的窄。按实际收益排序：

| 类型 | 效果 |
|---|---|
| 质量崩坏类（低质、糊、畸形） | 有效，降低概率 |
| 水印/文字/签名 | 有效 |
| 色调偏移类（偏绿、偏青） | **有效且必要**——暗部泛青是这套配方最常见的翻车方式 |
| 具体手指数量类 | 边际收益低，不如在构图阶段藏手 |

## 5. 与其他档位的对照

| 场景 | 参数 |
|---|---|
| 常规竖版壁纸 | 768×1664 / 28 步 / CFG 5.0 |
| 需要更强笔触 | 画风 LoRA 提到 0.7–0.75（不要再高） |
| 暗场景 | CFG 可降到 4.5，避免暗部被压死 |
| 横版 | 1664×768（同一套参数，只换宽高） |

## 6. 这套基线后来怎么用的

这 70 张 `768 × 1664` 的出图，最终成了 MOSS LoRA 的训练集。
也就是说：**这套参数不只用于出图，它同时决定了「我们想要的那个画风」的定义。**
